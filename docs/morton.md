# The Morton code in the zone guest

The zone decides which zone owns an entity, sorts its tree and picks its interest bands by one
30-bit code of the entity's cell. That code is a Morton code, and the zone does not define it.

## Where the code comes from

`thirdparty/misc/predictive_bvh.h` is generated by `lake exe bvh-codegen` of
`V-Sekai-fire/contract-spatial-oracle` and vendored unmodified, at commit
`032a449c9da84fe8df91f79336cb8cdd313c0082`. It defines `morton3d`, `morton3d_inverse`, `morton_of_aabb` and `morton_cell_of`.
`thirdparty/misc/morton_golden.tsv` comes from the same commit: 512 rows of `x`, `y`, `z` and the
code Lean computes.

| File | sha256 |
| --- | --- |
| `thirdparty/misc/predictive_bvh.h` | `e02e62cd2b75e5d7b51ae9e04f14920b96a869043afb7e452470d077841b75c7` |
| `thirdparty/misc/morton_golden.tsv` | `6e1a0ea27fa231e5d1a31f6af270542e8e3d03f908600f208fdef5d6e4046591` |

To move to a newer generator, copy both files from one commit of that repository and change the
commit and the two hashes here.

## What was removed

Until this change `src/zone/pbvh_adapter.h` defined the curve by hand, as `hilbert3d` and three
more functions, copied from the engine fork. That encoder was named after the Hilbert curve and
was not one: 87.5% of its consecutive codes were not neighbouring cells. Lean was corrected in
August 2026 and the hand-written C was not, because nothing held the two together. The account is
in `docs/morton.md` of the oracle repository.

The hand-written functions are deleted. The adapter keeps what the generator does not emit: the
128-bit helpers, the box predicates and the tree. Names that said which curve a value came from
now say what the value is:

| Before | Now |
| --- | --- |
| `entity_hilbert` | `entity_code` |
| `RelZone::zone_for_hilbert` | `RelZone::zone_for_code` |
| `ghost_hilbert` in a snapshot | `ghost_code` |
| `hilbert_code` | `curve_code` |
| the tree leaf's `hilbert` | `code` |

Every code changes with the encoder. A zone span, a journal or a peer that holds codes from the
old encoder does not agree with this one. The zone's journal stores entities and payloads, not
codes, and its tests pass unchanged.

## The gate

```sh
sh tools/morton_gate.sh [guest.elf ...]
```

1. No source line of the repository contains the old curve's name, in any case. First the lint
   must find a planted name in a scratch directory. This page is the one file the lint skips,
   because it records what was removed.
2. `tests/morton_vectors.cpp` includes the adapter as the guests do. For each golden row it makes
   the box of that cell in a scene of 1,024 cells an axis, and the code `morton_of_aabb` gives must
   be Lean's, and `morton_cell_of` at depth 10 must give that cell back.
3. Two controls must fail before the real run: a header with the old encoder's axis order, `z` in
   the top bit, which fails at row 1; and a golden file with one code raised by one, which fails at
   row 199.
4. Each ELF named on the command line must hold no string or symbol with the old name.

`tests.yml` runs the gate on the native build and `guests.yml` runs it on the four cross-built
guests.
